# 5.19 — Put the eval replay on the shared turn loop

Backlog row: [`backlog.md:143`](../backlog.md). Closes the last of 5.13.

## Problem

`src/eval/replay.ts` runs its own copy of the conversation turn. 5.17 extracted
`runConversationTurn` into [`src/conversation/turn.ts`](../src/conversation/turn.ts)
and moved the HTTP route onto it; replay was left behind.

The copy has drifted. Compared with production, replay:

- joins recall results with a bare newline instead of the `- Retrieved (<tool>): `
  prefix the Speaker prompt is written to expect
- never produces the MCP follow-up utterance, so an action-taking turn is
  measured as if the character said nothing about it
- does not strip narration, so `*shrugs*` counts as speech in every metric
- has no Mind timeout, so a hanging Mind hangs the eval instead of being
  abandoned at `mind_timeout_ms`
- never blends mood, so personality drift is invisible to the eval
- does not sanitize or moderate input
- writes nothing to the session log

A harness that measures the turn loop while running its own copy of it measures
the wrong thing. Every one of the four defects found by the text harness this
week (ERR-022, ERR-024, ERR-025, ERR-026) would have been invisible to an eval
run, because the code under test was not the code that ships.

## Decisions

**D1 — replay opens a real session.** `runConversationTurn` resolves everything
from a session: definition, instance, knowledge, project settings, deferred
context. Rather than fake that, replay materialises the fixture into a scratch
project through the ordinary storage API, calls `startSession`, runs the turns,
ends the session, and deletes the project in a `finally`.

**D2 — an explicit provider override, not a fake provider type.** Replay needs a
separately scripted Mind and Speaker per turn. `RunTurnOptions` gains an optional
`providers?: { speaker, mind }`; when present, provider resolution is skipped.
The alternative — registering a `stub` provider type in
[`src/providers/llm/factory.ts`](../src/providers/llm/factory.ts) and writing it
into project settings — would put test-only branches in the path every real
conversation takes. An override that production never sets is the smaller seam.

**D3 — fixture ids are documentation, not addresses.** Storage generates project,
NPC and instance ids. Replay creates the project, creates the definition, resolves
the instance through `getOrCreateInstance`, then overwrites its mutable state
(mood, memories, relationships, pulse) from the fixture. The fixture's own
`test-npc-1` style ids are ignored, so a fixture can no longer disagree with the
id scheme (see ERR-024).

**D4 — eval traffic is labelled.** `channel: 'eval'` joins the union in
[`src/telemetry/session-log.ts`](../src/telemetry/session-log.ts). Eval runs are
logged like everything else — that is the standing rule — but a reader must be
able to tell a scripted run from a played one.

**D5 — drop `TurnReport.timings.stages`.** `TurnResult.timings` already reports
mind, speaker, follow-up and wall time; nothing consumed `stages`
(`src/eval/cli.ts` prints three numbers). `followUpMs` is added in its place.
That leaves [`src/eval/timer.ts`](../src/eval/timer.ts) with no caller, so it and
`tests/unit/stage-timer.test.ts` are deleted rather than kept as production code
that only its own test uses.

## Scope

Changed: `src/eval/replay.ts`, `src/eval/cli.ts`, `src/conversation/turn.ts`
(the override), `src/telemetry/session-log.ts` (the channel).
Deleted: `src/eval/timer.ts`, `tests/unit/stage-timer.test.ts`.
Unchanged: the fixture format, so existing fixtures keep working.

## Test plan

`tests/e2e/eval-replay-shared-turn.test.ts`, driving a two-turn fixture whose
instance actually holds a memory:

1. **Deferred recall arrives in the shared format.** Turn 2's speaker prompt
   contains `- Retrieved (recall_memories): ` — the prefix the old copy did not
   write. This is the load-bearing assertion: it can only pass if the turn came
   from `runConversationTurn`.
2. **Narration is stripped.** A speaker response scripted as `*shrugs* Aye.`
   is reported as `Aye.`
3. **The session is real.** The run writes `session_started`, two `turn` records
   and `session_ended` to the session log, all with `channel: 'eval'`.
4. **Cleanup.** The scratch project does not exist after the run, including when
   a turn throws.
5. **Report shape.** Per-turn recall/tool metrics and the aggregate still
   populate, so `npm run eval` output is unchanged apart from `stages`.
