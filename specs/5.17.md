# 5.17 — Text harness for driving and validating NPCs

> **Revised after adversarial critique.** The first draft promised diagnostics for quantities that do
> not exist in this codebase. Corrections are marked `[C-n]` against the critique findings and kept
> visible, because several are facts about the system worth carrying forward independently of this tool.

## Problem

There is no way to hold a real conversation with an NPC and see what its mind is doing.

The web playground shows dialogue, not internals. The eval harness (`src/eval/`) is deterministic,
stubbed and scripted — it answers "did this regress", never "does this work". So the marquee features
have never been observed working:

- **Cycles have never run outside an explicit HTTP call.** `runDailyPulse`, `runWeeklyWhisper` and
  `runPersonaShift` are invoked only from `src/routes/cycles.ts`. Nothing schedules them.
- **Cross-session recall is unmeasured.** `deferred-recall.json` records 0% same-turn recall. Whether a
  fact survives to a later *session* is unknown.
- **A mind's affordances are invisible.** Nothing shows which knowledge depths an NPC may reach, or
  which tools it was offered versus chose.

## What the critique changed

Five findings invalidated parts of the original design. They are load-bearing, so they are stated as
facts about the system, not as spec history.

**`[C-1]` The Speaker prompt contains no knowledge at all.** `assembleSlimSystemPrompt`
(`src/core/context.ts:571-653`) carries the literal comment `// NO world knowledge section in slim
prompt` and takes no knowledge argument; the route passes `{}` (`conversation.ts:163-170`).
`getSessionContext` computes `resolvedKnowledge` (`session/manager.ts:495`) and nothing reads it.
Knowledge reaches a model only when the Mind calls `recall_knowledge`, and that result is deferred to
the *next* turn. So "tiers injected this turn" is structurally always zero and a granted-but-uninjected
tier is the normal state, not a bug. **Knowledge diagnostics split into static affordances and per-turn
recall events.**

**`[C-4]` STM, LTM and mood cannot change during a `talk`.** STM is appended only in `endSession`
(`manager.ts:329-334`); mood moves only on moderation `warn`/`exit` (`conversation.ts:380-388`) and on
the 0.1 drift inside `endSession`. Before/after deltas belong to `endsession` and `cycle`, not `talk`.

**`[C-6]` Sessions live in a `Map` (`session/store.ts:38-39`); the only disk write is inside
`endSession`.** Persisting by ending each turn would manufacture the very memory behaviour the harness
claims to observe — a summarization call, an STM entry and a mood drift per turn. The harness instead
calls `persistSession(state)` directly (exported, `storage/local/sessions.ts:30`, not gated on ending)
and `resumeSession(id, null)` on the next invocation.

**`[C-7]` `--stub` still requires `ENCRYPTION_KEY`.** `getSessionContext` unconditionally calls
`loadApiKeys` (`manager.ts:465`), which throws without the env var. Stub mode means no network and no
*provider* key; the encryption key is still needed to open the project.

**`[C-8]` The turn loop is not a callable function.** It is inline in the Hono handler
(`conversation.ts:74-446`). `src/eval/replay.ts:91-196` is already a second copy and has **already
drifted**: it omits the `- Retrieved (tool): ` prefix, skips the MCP follow-up speech, skips
`stripNarration`, and has no Mind timeout. A third copy would mean the harness validates its own loop
rather than production's, defeating the point.

## Design

### Shape

`npm run npc -- <command>`, implemented in `src/harness/`. In-process; no HTTP server.

**Extract the turn loop first.** `runConversationTurn()` moves out of `src/routes/conversation.ts` into
a module both the route and the harness call, and `src/eval/replay.ts` is repointed at it. This closes
backlog 5.13, whose own deferral note said "revisit if the harness is observed drifting from the
shipped route" — this is that trigger. `[C-8]`

Rejected alternative: driving the real route in-process via `routes.request(...)`. It works and needs
no extraction, but the route's rate limiter is 10/min per project/player/npc (`config.ts:19`) and would
429 an agent-driven loop, and it yields neither speaker timing nor a prompt dump.

**Constraint, revised.** No *behavioural* change to `src/core/*`. **Additive observability fields are
permitted** — specifically `tools_offered: string[]` on `MindResult`, set at the three return sites in
`mind.ts`. `[C-2]` The alternative is recomputing the offered list in the harness by copying
`mind.ts:319-331`, which can silently diverge from what the Mind actually saw; a validation tool that
lies about its subject is worse than one that touches a type.

### Commands

| Command | Behaviour |
|---|---|
| `world` | Projects, NPCs (mapped to their project), instances per player, open harness sessions |
| `talk <npcId> "<text>" [--player <id>] [--show-prompt]` | One turn; reply plus the diagnostic block |
| `inspect <npcId> [--player <id>]` | Core anchor, mood axes, STM, LTM, trait modifiers, relationships |
| `affordances <npcId>` | Static: knowledge depths existing vs granted; tools offered vs withheld |
| `endsession <npcId> \| --all` | Ends through the production path; prints what memory it produced |
| `cycle daily\|weekly\|persona <npcId>` | Runs the cycle, prints a before/after diff |
| `seed fishing\|office\|space [--clean]` | Scratch project from a starter pack, tagged as harness-made |
| `reset <npcId>` | Instance state back to fresh |
| `log [--session <id>] [--last N]` | Replays recorded turns |

`--player` defaults to a fixed `harness_player`, because the instance id derives from `npcId:playerId`
(`instances.ts:46-50`) and cross-session recall depends on it being stable. `[C-9]`

### The diagnostic block

Corrected to only report quantities that exist.

```
--- turn 7 | npc_mjxqkqbn (Aria) | session sess_... | player harness_player ---
reply     : "..."
mind      : completed  true          (false = 15s timeout or abort)
            called     recall_knowledge(query="tides") -> world_history, 1180 chars, truncated
            offered    recall_npc, recall_knowledge, recall_memories, exit_convo, lock_door
            withheld   give_item     (registry tool, not in conversation_tools)
                       flee_to       (game_event only)
recall    : deferred context injected into THIS turn : yes (2 recall results)
            this turn's recall deferred to           : next turn
state     : STM 4  LTM 2   mood v/a/d 0.40/0.55/0.30 (score 0.42)
            unchanged within a turn by design - see endsession and cycle
timing    : mind 812ms | speaker 640ms | wall 858ms
```

What each line is grounded in:

1. **Knowledge, per turn** `[C-1]` — not "tiers injected" but: did the Mind call `recall_knowledge`,
   which category matched, the `result_content.length`, and whether it ends in `... [truncated]`
   (`knowledge.ts:30`). Note the matcher is a substring test against id *and description*, first hit
   wins (`mind.ts:204-208`).
2. **Knowledge, static** — moved to `affordances`: depths that exist (`getAvailableDepths`) versus
   granted (`knowledge_access`). BLAST's knowledge base has a depth `0` tier, which
   `resolveCategoryKnowledge` includes (`key <= accessLevel`) while `getMindAvailableTools` only lists
   categories above level 0 (`tools.ts:347-349`) — so the rendering states the range, e.g.
   `world_history: depths 0-2 of 0-3`, never a bare "2 of 3". `[C-1]`
3. **Tools** `[C-2]` — `called` from `MindResult.tools_called`; `offered` from the new
   `tools_offered`; `withheld` computed as registry tools (`toolRegistry.getProjectTools`) minus
   offered, each tagged with why. The spec no longer references `getAvailableTools`,
   `getGameEventTools` or `hasToolPermission`: **all three have zero call sites outside
   `src/core/tools.ts`** and describe nothing that runs on this path. Actual withholding is the
   `permissions.denied` filter inside `getMindAvailableTools` (`tools.ts:389-391`).
   `NO_ACTION` and "model returned no tool calls" are indistinguishable (`mind.ts:367-380`); the block
   prints `completed` and does not pretend otherwise.
4. **Deferred seam** `[C-3]` — read `SessionState.deferred_mind_context` before and after the turn. It
   is a newline-joined string of `- Retrieved (tool): ` lines, so the count is "recall results", not
   "facts".
5. **State** `[C-4]` — current values only, with an explicit note that they cannot move within a turn.
6. **Timing** `[C-5]` — `mind` from `MindResult.duration_ms`; `speaker` and `wall` measured by the
   extracted turn function. Stub mode has no provider usage (`stub.ts:63-67`), so token figures fall
   back to the char/4 estimate and are labelled estimated.

`--show-prompt` dumps the exact Speaker prompt including any `[MIND CONTEXT]` block. `[C-18]`

### Persistence `[C-6]`

After every turn: `storage.persistSession(state)`. At the start of the next invocation:
`resumeSession(sessionId, null)`. `userId` is forced to `null` so storage resolves local
(`hybrid.ts:15-20`). Never call `endSession` implicitly.

Harness state at `data/harness/state.json`: `{ [npcId]: { sessionId, projectId, playerId, turns } }` —
one open session per NPC, since `seed office` makes multi-NPC normal. Add `/data/harness` to
`.gitignore` (only `/data/projects` and `/data/sessions` are ignored today). `[C-9]`

**Open-session hazard.** `resumeSession` restores a snapshot of the instance. `cycle` and `reset`
therefore **refuse** while a session is open for that NPC, naming `endsession` as the fix — rather than
silently ending it, since ending has side effects. `[C-6]`

### Cycles, sessions, seeding

- `cycle` resolves instances via `listInstancesForNpc` (`instances.ts:535`); `findInstanceById` is
  private to the route. Prints `memoriesPromoted / Retained / Discarded` and the `salience_threshold`
  used. **BLAST's threshold is 0.7**, which is the likely reason nothing has ever been promoted.
  `runWeeklyWhisper` works without a provider (direct promotion, `cycles.ts:236-241`); under `--stub`
  it will write stub text as LTM content, which the output must say. `[C-13]`
- `endsession` prints `memorySaved`, the memory content and its salience. Summarization failure leaves
  `memorySaved: false` while the call still succeeds (`manager.ts:339-345`), so "creates STM" is not
  guaranteed and the harness must not claim it did. `[C-14]`
- `seed` extracts `loadStarterPackIntoProject()` out of `src/routes/projects.ts:842-955` into
  `src/data/starter-packs.ts` rather than copying its two-pass id remapping. Seeded projects are tagged
  in settings so `world` can mark them and `--clean` can remove them. `[C-10]`

### Stub mode `[C-7]` `[C-12]`

`--stub` means no network and no *provider* key; `ENCRYPTION_KEY` is still required and its absence
must produce a clear message, not a stack trace. A wrong key surfaces as a generic `StorageError` whose
message contains `Decryption failed` (`secrets.ts:126-128`), so string-matching is the only available
signal — the harness says so rather than pretending to distinguish.

Mind and Speaker run concurrently, so a single shared stub would assign scripted responses by arrival
order. Use **two stub instances with fixed scripts**, and give the Mind stub a `recall_memories` call on
some turns or the deferred seam never lights up.

### Operational

- pino logs at `info` on stdout would interleave with the block; the harness entry point sets
  `LOG_LEVEL` to `warn` unless overridden. `[C-17]`
- Never import `src/index.ts` — it calls `serve()` at module load (`index.ts:340`). `[C-8]`
- `DATA_DIR` is stated explicitly for every run. This worktree's `data/` differs from the main
  checkout's, and `data/projects` is gitignored, so "the real BLAST" is ambiguous without it. `[C-7]`
- Turn cap: per NPC session, counted as user messages in `conversation_history`, refuses the turn and
  does **not** auto-end. Sessions never expire here — `startTimeoutCleanup` is server-only. `[C-11]`
- Testing `exit_convo` by typing jailbreak-shaped text will trip the moderator (`moderator.ts:47-58`);
  the harness must then end with `exitConvoUsed=true` or it creates STM from an aborted
  conversation. `[C-19]`

## Acceptance criteria

1. `runConversationTurn()` is extracted; the route, `src/eval/replay.ts` and the harness all call it,
   and the existing route e2e tests still pass unchanged.
2. `world` lists real projects and NPCs with their project ids and instances.
3. `talk` holds a multi-turn conversation across separate invocations, proven by a second command
   referring to something established in the first — via `persistSession`/`resumeSession`, never
   `endSession`.
4. The diagnostic block prints exactly the grounded fields above.
5. `affordances` reports knowledge depths as `granted-range of existing-range`, and tools as offered
   versus withheld with a reason.
6. `endsession` prints `memorySaved`, content and salience, and does not claim STM when false.
7. `cycle weekly` prints promoted/retained/discarded and the threshold used.
8. `seed office` produces a tagged multi-NPC project addressable by `talk`.
9. `--stub` runs the whole loop with no network and no provider key (`ENCRYPTION_KEY` still required,
   and its absence is explained).
10. `cycle` and `reset` refuse while a session is open for that NPC.
11. Turn cap refuses a turn without ending the session.
12. Telemetry is one JSONL per session id, replayable by `log`. `[C-15]`

## Test plan

Stub mode only, no network, no provider key. `DATA_DIR` set to a temp directory so tests stop writing
into the real `./data` — existing e2e tests do, which is why 155 stray `data/sessions/*.yaml` and three
`Broker Test Project` directories exist. `[C-16]`

- `tests/unit/` — diagnostic assembly from fixture inputs: depth ranges render correctly including a
  depth-0 tier; withheld tools carry the right reason; deferred-context counting.
- `tests/e2e/` — persistence: two turns with `sessionStore.clear()` between them (the existing
  new-process simulation, `tests/e2e/session-resume.test.ts:76-77`) and the second turn sees the first.
  Subprocess spawning is avoided as slow and Windows-fragile. `[C-16]`
- `tests/e2e/` — `endsession` reports `memorySaved` truthfully; `cycle weekly` moves entries and reports
  counts; `cycle` refuses against an open session; turn cap refuses without ending.
- `tests/e2e/` — the extraction is behaviour-preserving: existing conversation route tests pass.

## Out of scope

Scenario files, a simulated player, a judge model, automatic cycle scheduling (backlog 5.4).

## What this is expected to reveal

Stated so it can be checked, and narrowed after `[C-4]` — per-turn memory deltas were never observable,
so the original phrasing was untestable. The claims now: a fact established in one session will not be
recalled in a later one; BLAST has never promoted a memory, because its `salience_threshold` of 0.7 is
above what the summarizer assigns; and the deferred seam will show recall arriving exactly one turn
late, every turn.
