# 7.3 — Split the Speaker prompt into a cacheable prefix and a dynamic suffix

Backlog row: 7.3 in [`backlog.md`](../backlog.md), Tier 7. Pass E immediate win
([`research/09-npc-runtime/PROPOSAL.md`](../research/09-npc-runtime/PROPOSAL.md) §3 item 2). Depends on
7.1 for the `cached_input_tokens` signal that proves it works.

## Problem

Provider prompt caching needs a byte-identical prefix across requests, with the cache breakpoint placed
after the stable part. The slim Speaker prompt does the reverse on both counts:

- `assembleSlimSystemPrompt` ([`src/core/context.ts:575-654`](../src/core/context.ts)) emits the
  sections in this order: ROLE, CORE ANCHOR, PERSONALITY, **MOOD, RELATIONSHIP, PLAYER IDENTITY, KNOWN
  NPCS, MEMORIES, TODAY'S REFLECTION**, BEHAVIORAL GUIDANCE, SECURITY BOUNDARIES, INJECTION RESISTANCE,
  TASK. The bolded sections change turn to turn, and they sit in the middle, so the invariant tail can
  never be cached.
- The Anthropic provider wraps the whole system string in one `cache_control` block
  ([`src/providers/llm/anthropic.ts:141-150`](../src/providers/llm/anthropic.ts)); any change anywhere
  in the prompt is a miss.
- `augmentPromptWithMindContext` (`context.ts:769-775`) appends `[MIND CONTEXT]` after everything,
  which is the right place, but it is appended to a string that was already mixed.
- The OpenAI provider sends the system prompt as a plain message (`openai.ts:131-136`) with no
  `prompt_cache_key`, so its automatic prefix cache routes by chance.

Every turn therefore pays full prefill on roughly the largest part of the prompt. The role-play evidence
([`research/09-npc-runtime/e-roleplay-persona.md`](../research/09-npc-runtime/e-roleplay-persona.md)
§4) is unanimous on the fix: stable persona first, dynamic state last, breakpoint on the stable part.

## Decisions

1. **Two halves, one contract.** Add `assembleSlimSystemPromptParts(...)` with the same parameters as
   `assembleSlimSystemPrompt`, returning `{ stable: string; dynamic: string }`. Keep
   `assembleSlimSystemPrompt` as a thin wrapper that returns `stable + '\n\n' + dynamic`, so every
   existing caller and test keeps working.
2. **What is stable** (identical across every turn of a session for the same NPC definition): ROLE,
   CORE ANCHOR, the **definition-level** personality, KNOWN NPCS (project data, unchanged within a
   session), BEHAVIORAL GUIDANCE, INJECTION RESISTANCE, TASK. **What is dynamic:** MOOD, RELATIONSHIP,
   PLAYER IDENTITY, current personality deviation from baseline (if `formatPersonality`
   at `context.ts:99` blends instance drift into the text — split it, baseline in stable, drift in
   dynamic; if it does not, it is stable), MEMORIES, TODAY'S REFLECTION, SECURITY BOUNDARIES (it reads
   `securityContext.exitRequested`), and `[MIND CONTEXT]`. Section text is unchanged; only its position
   moves.
3. **The request carries the split.** `LLMChatRequest`
   ([`src/providers/llm/interface.ts:46-55`](../src/providers/llm/interface.ts)) gains
   `systemPromptPrefix?: string` and `cacheKey?: string`. Semantics: the effective system prompt is
   `prefix + '\n\n' + systemPrompt` when a prefix is present; providers that support explicit caching
   place the breakpoint after the prefix. Callers that do not set a prefix see no change.
4. **Providers:**
   - Anthropic: when `systemPromptPrefix` is set, `body.system` becomes two text blocks, `cache_control`
     **only on the first**; when absent, keep today's single block.
   - OpenAI: concatenate; set `prompt_cache_key` from `request.cacheKey` when present.
   - Gemini, Grok, Stub: concatenate.
5. **Callers pass the split.** `runConversationTurn` (`turn.ts:~225` where the slim prompt is built,
   and the Speaker call at `turn.ts:317-320`) and the voice pipeline (`pipeline.ts:~880-887`) use the
   parts: `systemPromptPrefix = stable`, `systemPrompt = augmentPromptWithMindContext(dynamic, ...)`,
   `cacheKey = \`${definition.id}:${definition.version ?? 0}\``. The follow-up leg (`turn.ts:372-397`)
   uses `buildFollowUpPrompt`, which is intentionally minimal, and is left as is.
6. **The Mind prompt is out of scope.** `assembleSystemPrompt` (the full prompt the Mind uses) has the
   same ordering problem and a per-turn tool-list change (`src/core/tools.ts:112-119, 415-418`); that is
   7.6, because offering `exit_convo` on every turn is a behaviour change with its own history
   (ERRORS.md over-triggering entries) and needs its own test.
7. **Cache minimums are the caller's problem to measure, not this item's to guess.** Anthropic and
   OpenAI only cache prefixes above a provider-specific token minimum (the ledger cites 1024 and 4096,
   unverified). This item does not pad the prefix; 7.1's `cached_input_tokens` will show whether the
   slim prefix clears the bar, and the harness decides what to do if it does not.

## Scope

Touch: `src/core/context.ts` (new parts function, reorder, wrapper), `src/providers/llm/interface.ts`,
`src/providers/llm/anthropic.ts`, `src/providers/llm/openai.ts` (and one-line concatenation in
`gemini.ts`, `grok.ts`, `stub.ts` if they read `systemPrompt` directly), `src/conversation/turn.ts`,
`src/voice/pipeline.ts` (the Speaker request only).

Do not touch: section wording, the Mind prompt, tools, `buildFollowUpPrompt`, `stripNarration`.

## Test plan

`tests/unit/slim-prompt-cacheable-prefix.test.ts`:
- Build parts twice for one definition and one instance whose `mood`, `relationships` and
  `short_term_memory` differ between the two calls, with a `securityContext` that flips
  `exitRequested`: `stable` is byte-identical; `dynamic` differs.
- `stable` contains the ROLE, CORE ANCHOR, BEHAVIORAL GUIDANCE, INJECTION RESISTANCE and TASK section
  headers and does not contain `[CURRENT MOOD]`, `[RELATIONSHIP` or `[MEMORIES` headers (use the exact
  header strings the formatters emit); `dynamic` contains them.
- `assembleSlimSystemPrompt(...)` equals `stable + '\n\n' + dynamic` and contains exactly the same set of
  section headers as before the change (guards against dropping a section during the reorder).
- `augmentPromptWithMindContext(dynamic, ctx)` puts `[MIND CONTEXT]` last.

`tests/unit/llm-system-prompt-split.test.ts`:
- Anthropic: with `systemPromptPrefix` the request body has `system` of length 2, `cache_control` on
  index 0 only, and index 1 text equal to `systemPrompt`; without a prefix, length 1 with
  `cache_control` (today's behaviour).
- OpenAI: the system message content is `prefix + '\n\n' + systemPrompt`; `prompt_cache_key` equals
  `request.cacheKey` when given and is absent otherwise.
- Stub provider still receives a single combined prompt (if the stub inspects `systemPrompt`, extend it
  to see the prefix too, so `deferred-recall-baseline.test.ts` keeps asserting on prompt content).

`tests/e2e/eval-replay-shared-turn.test.ts` and `tests/unit/deferred-recall-baseline.test.ts` stay green;
where they assert on `speakerPrompt` content, the assertion still holds because `TurnResult.speakerPrompt`
remains the full combined string.
