# 7.5 — `CognitionRuntime` v2: one streamed call that owns speech, actions and recall

Backlog row: 7.5 in [`backlog.md`](../backlog.md), Tier 7. Decision D16 in [`PRODUCT.md`](../PRODUCT.md) §6;
interface in §3.6. Evidence: [`research/09-npc-runtime/a-voice-turn-pipelines.md`](../research/09-npc-runtime/a-voice-turn-pipelines.md)
(shipped voice stacks run one call per turn with tools in-stream; nothing ships two independent calls),
[`diagnosis/turn-latency-path.md`](../research/09-npc-runtime/diagnosis/turn-latency-path.md) (the four
say-A-do-B hazards), [`BASELINE.md`](../research/09-npc-runtime/BASELINE.md) (the numbers to beat).

Two phases, one spec. Phase A is a refactor with an invariant suite; Phase B is the new runtime behind
the seam Phase A creates. Ship A before starting B.

## Problem

`runConversationTurn` ([`src/conversation/turn.ts:188`](../src/conversation/turn.ts)) hard-codes one
cognition design: a Mind loop and a Speaker stream started in parallel (`turn.ts:291-329`), recall
results stashed for the *next* turn (`turn.ts:366-370`, `deferred_mind_context`), and a third, fully
serial LLM call whenever the Mind used an action tool (`turn.ts:372-397`). The baseline shows what that
costs: the Speaker cannot use anything the Mind finds this turn, so it answers from a prompt that says
nothing about what was just asked; the action turn pays a second Speaker+TTS pass with no overlap; and
when the Mind and Speaker disagree the player hears one thing and sees another. `PRODUCT.md` §3.6
decided the cure is a seam — the runtime is one implementation behind an interface — and D16 approved
the second implementation: a single streamed generation that produces speech and tool calls together,
with recall fetched *before* the call rather than by a second model.

## Phase A — the seam, with the parallel runtime as its first implementation

### Decisions

1. **Interface.** New module `src/core/runtime.ts`:

   ```ts
   export interface CognitionInput {
     prompt: { stable: string; dynamic: string };   // from assembleSlimSystemPromptParts
     history: LLMMessage[];
     playerInput: string;                            // sanitized
     tools: Tool[];                                  // what this NPC may call this turn
     providers: { speaker: LLMProvider; mind: LLMProvider };
     cacheKey: string;
     signal: AbortSignal;                            // Mind timeout today; whole-turn budget later
     context: { definition; instance; knowledgeBase; projectId; sessionId; securityContext; userId };
   }

   export type CognitionEvent =
     | { type: 'text'; delta: string }                       // speech, in order
     | { type: 'tool_call'; call: ToolCall }                  // decided by the generation
     | { type: 'tool_result'; result: MindToolResult }        // executed by the runtime
     | { type: 'follow_up'; delta: string }                   // parallel runtime only
     | { type: 'done'; summary: CognitionSummary };

   export interface CognitionSummary {
     speech: string; followUp: string | null;
     toolCalls: ToolCall[]; toolResults: MindToolResult[];
     exit: { requested: boolean; reason: string | null } | null;
     deferredForNextTurn: string | null;                     // parallel runtime only
     timings: TurnTimings; usage: TurnResult['usage']; usageEstimated: boolean;
     mindResult: MindResult | null;                          // parallel runtime only; kept for the log
   }

   export interface CognitionRuntime {
     readonly name: 'parallel' | 'single';
     generate(input: CognitionInput): AsyncIterable<CognitionEvent>;
   }
   ```

   The stream shape is not decoration: the voice pipeline will consume `text` events into the
   `SentenceDetector` (backlog 7.14), which is why `generate` yields rather than returns.

2. **`ParallelRuntime`** (`src/core/runtime/parallel.ts`) is the current code moved, not rewritten:
   the Mind loop and Speaker stream in parallel, the deferred-recall stash, the follow-up leg, the
   Mind timeout. It yields `text` as the Speaker streams, `tool_call`/`tool_result` from the Mind's
   `tools_called`, `follow_up` deltas, and `done` with the same numbers `runConversationTurn` computes
   today. Behaviour is byte-for-byte what ships now.

3. **`runConversationTurn` becomes the host.** It keeps everything that is not cognition —
   sanitize, moderate, prompt assembly, provider resolution, session history, mood blending, exit
   handling, the session log, `TurnResult` — and delegates the middle to `runtime.generate()`. It
   consumes the events to build `responseText`, `followUpText`, `toolCalls`, `toolResults`,
   `exitConvoResult`, `deferredContextForNextTurn`, timings and usage exactly as before.

4. **Selection.** `ProjectSettings.cognition_runtime?: 'parallel' | 'single'` (schema + type),
   default `'parallel'`; `RunTurnOptions.runtime?: CognitionRuntime['name']` overrides it (the
   playground's `--runtime` flag, below). A factory `selectRuntime(name)` in `runtime.ts`.

5. **Playground.** `play` gains `--runtime parallel|single`, threads it through `PlayOptions` to
   `runConversationTurn`, and the `state` record reports `runtime: <name>`.

6. **Refactor invariant.** No test changes except additions. `tests/e2e/replay-runner.test.ts`,
   `eval-replay-shared-turn.test.ts`, `deferred-recall-baseline.test.ts`, `turn-latency-visibility.test.ts`
   and the playground suite pass unchanged. The stub-mode playground scenarios produce identical
   `turn` records (minus timings) before and after.

### Phase A test plan

`tests/unit/cognition-runtime-seam.test.ts`:
- `selectRuntime('parallel')` returns the parallel runtime; unknown names throw.
- `runConversationTurn` with `runtime: 'parallel'` and stub providers yields the same `TurnResult`
  fields as before the refactor for: a plain turn, a turn whose Mind calls `recall_memories` (result
  deferred to the next turn), a turn whose Mind calls an action tool (follow-up produced), and a turn
  whose Mind calls `exit_convo`.
- Event order from `ParallelRuntime.generate`: `text*`, then `tool_call`/`tool_result`, then
  `follow_up*`, then exactly one `done`.
- Project setting `cognition_runtime` is honoured; `RunTurnOptions.runtime` overrides it.

`tests/e2e/playground-play.test.ts` gains one case: `--runtime parallel` appears in the `state` record.

## Phase B — `SingleCallRuntime`

### Decisions

1. **One call.** `SingleCallRuntime.generate` makes exactly one `streamChat` request with:
   `systemPromptPrefix = prompt.stable`, `systemPrompt = prompt.dynamic + recallSection + singleCallTask`,
   `messages = history`, `tools = actionTools`, `cacheKey`. Text deltas are yielded as `text`; tool
   calls are collected as the provider surfaces them (all three providers stream text deltas and
   surface tool calls in the same call — Anthropic and OpenAI at the end, Gemini inline). `mindMs` is
   `null`; `speakerMs`/`speakerTtftMs` are the call's; `followUpMs` is always `null`.

2. **Recall is fetched before the call, deterministically.** New module `src/core/recall.ts`
   extracts the three lookups from `executeMindTool` (`src/core/mind.ts:139-…`) into pure functions
   used by both the Mind tools and the runtime:
   - `recallMemoriesFor(instance, text, limit)` — `matchMemoriesByQuery` over STM+LTM
     (`src/core/memory.ts:167`), same matcher the tool uses.
   - `recallKnowledgeFor(definition, knowledgeBase, text, tokenBudget)` — categories whose id or
     description shares a term with the input, resolved with `resolveCategoryKnowledge` at the NPC's
     access level, bounded by a token budget (a named constant next to `KNOWLEDGE_SECTION_TOKEN_BUDGET`).
   - `recallNpcsFor(definition, text, storage)` — network entries whose name appears in the input,
     rendered at their granted tier.
   The results form a `[RELEVANT TO WHAT WAS JUST SAID]` section appended to the dynamic suffix
   (empty section omitted). `executeMindTool` calls the same functions, so the Mind tools and the
   pre-fetch cannot drift. Term matching stays as dumb as the tools are today; 6.6 (embedding recall)
   improves both at once.

3. **Recall tools are not offered to the model in single mode.** `actionTools` =
   `getMindAvailableTools(...)` minus `recall_npc`, `recall_knowledge`, `recall_memories`
   (`isRecallTool`, `src/core/tools.ts`). There is no second round-trip in the budget; if the
   pre-fetch missed, the harness says so and the fix is the matcher, not another LLM call.

4. **Actions execute after the stream ends, in the order emitted**, through the same
   `executeMindTool`/`toolRegistry.executeTool` path the Mind uses (permissions, validator, cooldowns
   unchanged). Results are yielded as `tool_result` and written back for the next turn as facts the
   way Mind results are today (`deferredForNextTurn` carries the `- Retrieved (<tool>): ...` lines for
   action results only). **No follow-up call:** the model produced its line knowing what it was
   about to do. `exit_convo` in-stream sets `exit`; the host runs `handleExitConvo` as it does now.
   Blocking-vs-composing semantics (§3.7 rule 2) are not this item; every action composes.

5. **Task section for one call.** New `formatSingleCallTask(definition, voiceMode, hasActionTools)`
   in `src/core/context.ts`: speak as the character in one to three sentences; you may call an
   action tool when the situation clearly calls for it; then the exit rules. The exit rules text
   currently inline at `src/core/mind.ts:115-119` moves to one exported constant used by both the
   Mind prompt and this task, so the over-triggering guard has one copy.

6. **Coherence check the host can enforce.** If the generation produced `exit_convo` but no text,
   the host uses the existing exit fallback line; if it produced text but the moderator had already
   forced an exit, the moderator wins (unchanged). Nothing else is second-guessed — that is the point.

7. **Default stays `parallel`.** Flipping the default is a separate, measured decision after the A/B
   below, recorded in `PRODUCT.md` §3.6.

8. **Out of scope, filed:** the voice pipeline consuming `generate()` and streaming sentences to
   TTS (7.14); blocking actions and completion signals (§3.7 rule 5); the C# runtime and a
   `tests/conformance/` fixture (Unity is out of scope for this pass; conformance lands with the
   port); tool preconditions on game state (7.9); patience (7.10).

### Phase B test plan

`tests/unit/single-call-runtime.test.ts` (stub providers; `StubLLMProvider` already scripts
`text` and `toolCalls` together):
- Exactly one `streamChat` call per turn (spy), with `tools` containing no recall tool and
  `systemPromptPrefix` equal to `prompt.stable`.
- Text and an action tool call in one scripted response: `text` events carry the speech, the tool is
  executed once after the stream, `tool_result` is yielded, `followUp` is `null`, and no second
  `streamChat` happens.
- `exit_convo` in the scripted response: `done.exit.requested === true` with its reason.
- Timings: `mindMs === null`, `speakerTtftMs <= speakerMs`, `followUpMs === null`.

`tests/unit/recall-prefetch.test.ts`:
- `recallMemoriesFor` returns the memory sharing a term with the input and not the unrelated one;
  respects `limit`.
- `recallKnowledgeFor` includes a category whose description shares a term, at the granted depth,
  excludes ungranted categories, and stops at the token budget.
- `recallNpcsFor` matches a network entry by name, case-insensitively.
- The Mind's `recall_*` tools and the pre-fetch return the same content for the same input
  (drift guard).

`tests/unit/cognition-runtime-seam.test.ts` gains: `selectRuntime('single')`; project setting
`'single'` selects it.

`tests/e2e/playground-play.test.ts` gains: the same stub scenario run with `--runtime single`
produces a `turn` record whose `timings.mindMs` is `null` and whose `state.runtime` is `single`.

Live gate (not CI): `deferred-recall-strict.json` with `--runtime single`, 5 trials on gpt-4o and
gemini-2.5-flash, must match or beat the parallel runtime's pass rates in `BASELINE.md`, and
`speakerTtftMs` p50 must not exceed the parallel runtime's. Record both in `BASELINE.md`.

## Scope

Phase A touches: new `src/core/runtime.ts`, new `src/core/runtime/parallel.ts`,
`src/conversation/turn.ts` (host), `src/schema/index.ts` + `src/types/project.ts`
(`cognition_runtime`), `src/harness/playground.ts` + `src/harness/cli.ts` (`--runtime`).
Phase B adds: `src/core/runtime/single.ts`, `src/core/recall.ts`, `src/core/context.ts`
(`formatSingleCallTask`, recall section), `src/core/mind.ts` (use `recall.ts`; export the exit rules
constant), `src/core/tools.ts` only if an `actionToolsFor` helper is cleaner than filtering at the call site.

Do not touch: `src/voice/pipeline.ts` (7.14), providers, the Mind loop's own logic beyond the two
extractions above, prompt section wording other than the new task section.
