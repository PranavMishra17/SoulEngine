## Problem

Two tools exist and neither is a playground.

- `npm run npc -- talk <npcId> "text"` ([`src/harness/cli.ts:232-290`](../src/harness/cli.ts)) drives a
  real NPC against real providers, one process per turn, and prints a human-readable diagnostic
  block. An external agent driving it has to spawn a process per line and parse prose.
- `npm run eval <fixture>` ([`src/eval/replay.ts:135`](../src/eval/replay.ts)) replays scripted
  conversations with **canned** LLM responses (`StubLLMProvider` per turn, `replay.ts:157-167`). It
  proves orchestration, never behaviour.

So there is no way to (a) run many turns against the real cognition stack from a program, (b) inject a
world event between turns, (c) assert on tool calls, exits and recall against a real model, (d) rerun
the same scenario k times to catch intermittent say-A-do-B failures, or (e) record a real session once
and replay it in CI for free. Everything the Pass E proposal wants to measure — the parallel runtime's
baseline, the single-call runtime that replaces it, the endpointing and cache wins from 7.1-7.3 — needs
those five things.

## Decisions

### 1. Surface

A new subcommand on the existing CLI, sharing its provider resolution, session handling and storage:

```
npm run npc -- play --npc <npcId> [--player <id>] [--stub] [--scenario <file>] [--trials <k>]
                    [--record <cassette.json>] [--replay <cassette.json>] [--end-session]
```

`play` is added as one `case` in `main()` (`src/harness/cli.ts:528-566`) that delegates to a new
module `src/harness/playground.ts`. The human-readable commands are untouched.

### 2. Protocol — one JSON object per line, both directions

Without `--scenario`, `play` reads stdin line by line until `{"end": true}` or EOF. Every input line is
one JSON object with exactly one of these keys; every response is one JSON object with a `type`.

| Input | Effect | Output |
|---|---|---|
| `{"say": "<text>"}` | Runs one turn through `runConversationTurn` (`src/conversation/turn.ts:188`) exactly as `cmdTalk` does (`cli.ts:247-253`), `channel: 'playground'` | `{"type":"turn", ...}` (fields below) |
| `{"event": {"text": "<text>", "salience"?: 0..1}}` | **Stopgap until 7.8's fact table:** writes a short-term memory tagged `world_event` via `createMemory` (`src/core/memory.ts:17-33`) onto the instance and persists it. Documented in the output as `"mechanism":"memory-stopgap"` so nobody mistakes it for the real inbox | `{"type":"event","accepted":true,"mechanism":"memory-stopgap"}` |
| `{"inspect": true}` | No turn | `{"type":"state", ...snapshot}` (fields below) |
| `{"state": {...}}` | Reserved for 7.9 | `{"type":"error","code":"unsupported","message":"quest state arrives with backlog 7.9"}` |
| `{"end": true}` or EOF | Persists the session (as `cmdTalk` does at `cli.ts:284`, "resume, do not restart"); with `--end-session`, calls `endSession` instead so summarisation and memory writes can be observed | `{"type":"end","sessionId","turns","summarized":bool}` |
| anything else | — | `{"type":"error","code":"bad-input","message"}`; processing continues |

Errors from a turn (`TurnError`) become `{"type":"error","code":"turn-failed","message"}` and the loop
continues. Nothing but JSON goes to stdout; logs stay on stderr (the harness logger already does this —
verify, and route if not).

**`turn` record.** Built by a pure function `buildTurnRecord(...)` from `TurnResult`
(`turn.ts:101-133`) plus before/after snapshots, so it is unit-testable without a session:

```
type: 'turn', turn: n, sessionId, input (sanitized text), reply, followUp: string|null,
tools: { offered: string[], called: [{name, arguments, status}], denied: string[] }   // from computeAffordances, src/harness/diagnostics.ts:52
timings: TurnTimings (incl. speakerTtftMs, followUpTtftMs from 7.1)
usage: TurnResult.usage (per leg, incl. cached_input_tokens)                             // from 7.1
security: { moderationAction, sanitizationViolations }
exit: { requested: boolean, forcedByModeration: boolean, reason: string|null }         // from exitConvoResult
deferred: { injected: string|null, forNextTurn: string|null }                           // TurnResult.deferredContextInjected / ForNextTurn
delta: { mood: {before, after}, relationship: {before, after} | null, memories: {stm: [before, after], ltm: [before, after]} }
```

**`state` record.** `sessionId`, `turns`, `npcId`, `playerId`, `mood`, `relationship`, memory counts,
tools currently offered (same `computeAffordances`), and the effective provider names.

### 3. Scenario files — scripted player, events, expectations, trials

`--scenario <file>` replaces stdin with a script. Schema `PlaygroundScenarioSchema` lives next to the
fixture schema in [`src/schema/eval.ts`](../src/schema/eval.ts) and **reuses its `npc` object**
(`eval.ts:61-65`) so an NPC can be embedded; alternatively `npcId` names an existing NPC in the project
(as `--npc` does). One of `npc` / `npcId` is required.

```
{
  name, description,
  npc?: <ConversationFixtureSchema.npc>,  npcId?: string,
  player?: { id?: string, script: string[] },              // scripted lines, one per turn
  events?: [{ afterTurn: n, text: string, salience?: number }],
  expect?: [{ turn: n,
              toolsCalled?: string[], toolsNotCalled?: string[],
              recallFacts?: string[],                         // substring match on reply, as replay.ts does
              replyMatches?: string,                          // regex source
              exitRequested?: boolean,
              moderationAction?: string }],
  trials?: number                                            // default 1; --trials overrides
}
```

The **LLM-driven persona player** (promptfoo-style simulated user) is **not** this item — it is
filed as 7.12. A scripted player already lets Claude Code or CI drive deterministic scenarios, and the
external-agent-on-stdin path covers the improvised case.

When `npc` is embedded, the scenario is materialised into a scratch project and torn down afterwards
the way `runReplay` does (`replay.ts:135-…`). Extract that materialise/teardown pair into a shared
helper (e.g. `src/eval/scratch-project.ts`) used by both replay and playground rather than copying it.

### 4. Scoring — pass^k, per-expectation rates, latency percentiles

Each trial opens a **fresh session**, runs the script (events fire after their named turn), evaluates
every expectation against that turn's record, then ends and deletes the session. After all trials:

```
{ type: 'summary', scenario, trials: k, passed: m,
  passK: m === k ? 1 : 0,                                     // tau-bench pass^k: all k succeed
  perExpectation: [{ turn, check, passRate }],
  latency: { wallMs: {p50, p95}, speakerTtftMs: {p50, p95}, speakerMs: {p50, p95} },
  usage: { inputTokens, outputTokens, cachedInputTokens }     // totals across trials
}
```

The process exit code is `0` when `passK === 1` and `1` otherwise, so a scenario is a CI gate.
Every `turn` record is still emitted during scenario runs (prefixed with `trial: i`), so a failing
trial is diagnosable from the same stream.

### 5. Cassette — record real provider traffic once, replay it deterministically

New module `src/providers/llm/cassette.ts`:

- `RecordingLLMProvider(inner: LLMProvider, cassette)` implements `LLMProvider`; `streamChat` passes
  every chunk through unchanged and appends `{ key, request: {prefixChars, promptChars, messageCount, toolNames}, chunks }`.
- `PlaybackLLMProvider(cassette)` yields the recorded chunks for a matching key; on a miss it throws
  `CassetteMissError` naming the closest recorded request so the drift is diagnosable.
- `key` = SHA-256 over a canonical JSON of `{ systemPromptPrefix, systemPrompt, messages, toolNames }`.
  Timing is not recorded (replays are instant); `usage` chunks are replayed as recorded so cache-token
  reporting survives replay.
- File format `{ version: 1, entries: [...] }`, written on `end`.

`--record <file>` wraps the resolved provider and passes it through `RunTurnOptions.providers`
(`turn.ts:87`) as both `speaker` and `mind`; `--replay <file>` does the same with the playback provider
and needs no API key. Known limitation, same one replay already accepts: the `providers` override
bypasses per-project `mind_provider` selection (`turn.ts:249-269`), so record mode uses one provider
for both legs. Say so in the `state` record (`providers.overridden: true`).

### 6. Out of scope, filed separately

- Dollar cost per turn: needs a maintained price table; tokens are reported now. → 7.11.
- LLM persona player. → 7.12.
- World-event inbox as facts with scope and TTL (replaces the memory stopgap). → 7.8.
- Quest state injection and `expect.visibleTools`. → 7.9 (the protocol reserves `state`).
- dotenv loading in `src/harness/bootstrap.ts` (diagnosis item 8): leave the harness's env story as is.
- Documentation of the protocol in `documentation/`: the orchestrator writes it from this spec.

## Scope

Touch: `src/harness/cli.ts` (one `case 'play'` + flag parsing for the new flags), new
`src/harness/playground.ts` (loop, record builders, scenario runner, scoring — keep pure functions
exported for tests), `src/schema/eval.ts` (scenario schema + type), new `src/providers/llm/cassette.ts`,
`src/conversation/turn.ts:76-77` (add `'playground'` to the `channel` union; also
`src/telemetry/session-log.ts` if the union is declared there), `src/eval/replay.ts` only to call the
extracted scratch-project helper, new `src/eval/scratch-project.ts`, `package.json` only if a script
alias is wanted (not required — `npm run npc -- play` works as is).

Do not touch: prompt assembly, tools, providers other than the new cassette module, `runConversationTurn`
beyond the channel union.

## Test plan

`tests/unit/playground-protocol.test.ts` (pure functions, no session):
- `parseInputLine` maps `say` / `event` / `inspect` / `end` to commands, `state` to an
  `unsupported` error, malformed JSON and unknown keys to `bad-input`.
- `buildTurnRecord` from a hand-built `TurnResult` + snapshots produces every field in §2, including
  `delta.memories` counts and `exit.reason`, and never includes the raw system prompt.

`tests/unit/llm-cassette.test.ts`:
- Recording passes chunks through unchanged and stores one entry per `streamChat` call.
- Playback returns byte-identical chunks (including the `usage` chunk) for the same request; a changed
  message, prefix, or tool set produces a different key and a `CassetteMissError` naming the nearest entry.
- Round-trip through the file format.

`tests/unit/playground-scenario.test.ts`:
- Schema: accepts embedded `npc` or `npcId`, rejects neither/both, rejects `expect.turn` beyond the
  script length.
- `evaluateExpectations` against synthetic turn records: each check type passes and fails correctly.
- `summarise` over trial results: 3 trials with one failure gives `passK 0` and the right
  `perExpectation` rates; p50/p95 computed over the recorded timings.

`tests/e2e/playground-play.test.ts` (in-process, `--stub`, scratch project — follow
`tests/e2e/eval-replay-shared-turn.test.ts` for setup):
- Drive `runPlay` with an in-memory input iterable `[say, event, inspect, say, end]` and collect output:
  record types in order `turn, event, state, turn, end`; the second `turn` has `timings.speakerTtftMs`
  and `usage.speaker`; `event.mechanism === 'memory-stopgap'` and the following `state` shows the STM
  count increased by one.
- A scenario file `tests/fixtures/playground/deferred-recall.json` mirroring
  `tests/fixtures/conversations/deferred-recall.json` with `trials: 2`: the summary reports `trials 2`,
  `passK 1`, and the process-exit value `0`.
- A scenario `tests/fixtures/playground/abusive-player.json` whose script contains a jailbreak line
  (take the phrasing from `JAILBREAK_PHRASES`, `src/security/moderator.ts:15`) and expects a
  non-`allow` `moderationAction` on that turn: passes in stub mode because moderation is keyword-based.
- Record then replay: run one scenario with `--record` to a temp file, then again with `--replay` and
  **no fallback provider**; both produce equal `reply` text per turn.

Existing suites stay green; `replay-runner` and `eval-replay-shared-turn` must still pass after the
scratch-project extraction.
