# 7.1 — Make text-turn latency and cache hits visible

Backlog row: 7.1 in [`backlog.md`](../backlog.md), Tier 7. First of the Pass E immediate wins
([`research/09-npc-runtime/PROPOSAL.md`](../research/09-npc-runtime/PROPOSAL.md) §3 item 3). Lands
before 7.2 and 7.3 so each of them has a before/after number.

## Problem

`TurnTimings` ([`src/conversation/turn.ts:90-99`](../src/conversation/turn.ts)) records `mindMs`,
`speakerMs`, `followUpMs` and `wallMs`. It cannot say when the first token of speech arrived: the
Speaker loop at `turn.ts:317-324` accumulates the whole stream before `speakerMs` stops. For a
voice-first product the number that matters is time to first token, because it bounds time to first
audio. Nothing records whether the provider served the system prompt from cache either, so the
prompt-caching work in 7.3 would have no way to prove it hit.

No test asserts any latency bound. `tests/unit/deferred-recall-baseline.test.ts` records a baseline but
never fails on time, so a change that adds a serial leg to the turn (the pattern
[`research/09-npc-runtime/diagnosis/turn-latency-path.md`](../research/09-npc-runtime/diagnosis/turn-latency-path.md)
found three of) passes CI.

The voice path already has `LatencyTracker` with `firstToken` and `firstAudio` marks
([`src/voice/pipeline.ts:98-138`](../src/voice/pipeline.ts), backlog 4.6). This item brings the text
path to parity and adds the cache signal to both.

## Decisions

1. **`TurnTimings` gains `speakerTtftMs: number | null`** — milliseconds from the Speaker request to
   the first chunk whose `text` is non-empty; `null` if the stream produced no text. When a follow-up
   leg runs (`turn.ts:372-397`), `followUpTtftMs: number | null` is measured the same way.
2. **Provider usage carries cache tokens.** `LLMStreamChunk.usage`
   ([`src/providers/llm/interface.ts:19-22`](../src/providers/llm/interface.ts)) gains optional
   `cached_input_tokens?: number`. The Anthropic provider maps `cache_read_input_tokens` into it; the
   OpenAI provider maps `prompt_tokens_details.cached_tokens`. Gemini and Grok leave it undefined. No
   provider-specific field names leak past the provider files.
3. **`TurnResult` exposes usage.** `TurnResult` (`turn.ts:101-126`) gains
   `usage: { speaker?: Usage; mind?: Usage; followUp?: Usage }` where `Usage` is the chunk usage type,
   so callers see input, output and cached input tokens per leg. The session-log turn record written at
   `turn.ts:440-477` includes `speakerTtftMs`, `followUpTtftMs` and the usage object.
4. **The text harness prints them.** `npm run npc -- talk` (`renderTurnDiagnostics`,
   [`src/harness/diagnostics.ts:141`](../src/harness/diagnostics.ts)) shows ttft beside the existing
   stage timings and prints `cache: <n> read` when `cached_input_tokens` is present.
5. **One latency assertion exists.** A unit test drives `runConversationTurn` with stub providers and
   asserts an orchestration-overhead bound: `wallMs - max(mindMs, speakerMs) <= 250ms`. Stubs make the
   provider time near zero, so the bound guards exactly the thing that regresses silently — added
   serial work in the turn loop. The number is generous on purpose; tighten later with harness data.
6. **No behaviour change.** Prompts, tool handling, ordering and outputs are identical; this item only
   measures and reports.

## Scope

Touch:
- `src/conversation/turn.ts` — `TurnTimings`, `TurnResult`, the two stream loops, the session-log record
- `src/providers/llm/interface.ts` — `usage.cached_input_tokens`
- `src/providers/llm/anthropic.ts`, `src/providers/llm/openai.ts` — map the cache field on the final chunk
- `src/providers/llm/stub.ts` — if needed, let a stub yield a configurable delay before its first chunk
  so ttft is testable (additive option only)
- `src/harness/diagnostics.ts` — render ttft and cache read
- `src/telemetry/session-log.ts` — only if the turn record type is declared there

Do not touch: `src/voice/pipeline.ts` (its tracker already has these marks), prompt assembly, tools.

## Test plan

`tests/unit/turn-latency-visibility.test.ts`:
- Speaker stub yields an empty chunk, waits ~40ms, then yields text: `speakerTtftMs >= 40` and
  `speakerTtftMs <= speakerMs`.
- Speaker stub yields only a `done` chunk with no text: `speakerTtftMs === null`.
- A final chunk with `usage.cached_input_tokens: 1234` appears in `result.usage.speaker.cached_input_tokens`
  and in the appended session-log record.
- Orchestration-overhead bound: with zero-delay stubs, `wallMs - Math.max(mindMs ?? 0, speakerMs) <= 250`.

`tests/unit/llm-usage-cache-tokens.test.ts`:
- Anthropic provider: a `message_delta` (or equivalent final) event carrying
  `usage.cache_read_input_tokens = 700` yields `cached_input_tokens = 700` on the `done` chunk.
- OpenAI provider: `usage.prompt_tokens_details.cached_tokens = 512` yields `cached_input_tokens = 512`.
- A provider event with no cache fields yields `cached_input_tokens` undefined, not 0.

Existing suites (`tests/e2e/replay-runner.test.ts`, `tests/e2e/eval-replay-shared-turn.test.ts`,
`tests/unit/deferred-recall-baseline.test.ts`) stay green unchanged.
