# 7.6 — A cacheable Mind prompt with a conservative action instruction

Backlog row: 7.6 in [`backlog.md`](../backlog.md), Tier 7. Re-scoped 2026-09-12 after reading the
code the original row cited.

## Problem

The original row said `exit_convo` was force-added per turn and defeated Mind-prompt caching.
Reading it: `getMindAvailableTools` (`src/core/tools.ts:350-…`) already adds `exit_convo`
unconditionally, so the Mind's tool list is constant for a session, and the function with the
per-turn force-add, `getAvailableTools` (`tools.ts:~90-140`), has **no callers**. That premise is
gone. Two real problems remain in the same code:

1. **The Mind prompt cannot be cached at all.** `buildMindSystemPrompt`
   ([`src/core/mind.ts:33-…`](../src/core/mind.ts)) writes the conversation history and the
   player's current line *into the system prompt* (`mind.ts:87-92`, `[CURRENT CONVERSATION]`) and
   sends `messages: []`. Every byte of the system prompt changes every turn. The baseline
   ([`research/09-npc-runtime/BASELINE.md`](../research/09-npc-runtime/BASELINE.md)) shows the Mind
   at ~2,400 input tokens per turn — more than the Speaker — and 750-1,370 ms, often the longer of
   the two parallel legs. The parallel runtime remains the default, so this is the largest
   remaining prefill on the live path, and 7.3's prefix split already exists to receive it.
2. **The action instruction invites over-triggering.** `mind.ts:106` reads "These are YOUR tools —
   use them proactively when appropriate", the opposite shape of the `exit_convo` rules that ended
   that tool's over-firing (`EXIT_CONVO_RULES`, `tools.ts:12`). Anthropic's own tool-use guidance,
   cited in [`c-tool-gating-and-quests.md`](../research/09-npc-runtime/c-tool-gating-and-quests.md),
   shows models over-call tools when told to be proactive.

## Decisions

1. **Split the Mind prompt like the Speaker's.** New `buildMindSystemPromptParts(definition, instance)`
   returning `{ stable, dynamic }`:
   - stable: role, identity (baseline personality via `generatePersonalityDescription(baseline)`
     without modifiers), the tool guidance block, the decision framework, `EXIT_CONVO_RULES` with
     the Mind's `NO_ACTION` clause. Byte-identical across a session.
   - dynamic: mood (`formatMoodForPrompt`), trait drift (`describeTraitShifts`), and nothing else.
   `buildMindSystemPrompt` stays as a wrapper returning `stable + '\n\n' + dynamic` for any caller
   that still wants one string, but `runMindAgentLoop` uses the parts.
2. **History and the player line become messages.** `runMindAgentLoop` sends
   `systemPromptPrefix: stable`, `systemPrompt: dynamic`, `cacheKey` (same key the Speaker uses:
   `${definition.id}:${definition.version ?? 0}`; thread it through `runMindAgentLoop`'s
   parameters or `CognitionInput`), and `messages: [...conversationHistory, { role: 'user', content: userMessage }]`
   instead of `[]`. The `[CURRENT CONVERSATION]` block is removed from the prompt. The second Mind
   call (after tool execution) keeps its current message construction but on top of the same split.
   `MindResult.usage` gains `cached_input_tokens` (summed from the chunks' `usage.cached_input_tokens`
   that 7.1 added) so `TurnResult.usage.mind` and the playground can show the Mind's cache hits.
3. **Conservative action instruction.** Replace the `mind.ts:106` sentence with the negative-list
   shape: call an action tool only when the player's words plainly require it (a payment made, an
   item handed over, a request the NPC fulfils or refuses, a threat that warrants guards); never for
   small talk, questions, or anything a line of dialogue answers; when in doubt, `NO_ACTION`. Keep the
   two worked examples but frame them as "call X only when...". Do not touch `EXIT_CONVO_RULES`.
4. **Delete `getAvailableTools` and its force-add block.** It has no callers. `filterByPermissions`
   and `isBuiltinTool` stay if other code uses them.
5. **No change to which tools are offered or to `exit_convo` handling.** The executor's
   "exit_convo cannot be denied" rule (`tools.ts:154`) stays.

## Scope

Touch: `src/core/mind.ts` (`buildMindSystemPromptParts`, wrapper, `runMindAgentLoop` request
shape, action instruction), `src/core/tools.ts` (delete dead function), `src/core/runtime/parallel.ts`
only to pass `cacheKey` into `runMindAgentLoop` if that is the cleanest route.

Do not touch: `SingleCallRuntime`, `EXIT_CONVO_RULES`, `getMindAvailableTools`, providers, the Speaker prompt.

## Test plan

`tests/unit/mind-prompt-cacheable-prefix.test.ts`:
- Build parts twice for one definition with two instances differing in mood and `trait_modifiers`:
  `stable` byte-identical, `dynamic` differs, and neither contains the player line or history text
  passed to the old builder.
- `runMindAgentLoop` with a spy on the Mind stub's `streamChat`: the first call carries
  `systemPromptPrefix === stable`, `messages` ending with `{ role: 'user', content: <player line> }`
  and containing the prior history in order, `cacheKey` set, and no `[CURRENT CONVERSATION]` text in
  either prompt half.
- The action instruction contains "when in doubt" / `NO_ACTION` wording and does not contain
  "proactively".
- `getAvailableTools` is no longer exported (a type-level import test or `expect(tools).not.toHaveProperty(...)`).

Existing suites stay green: `tests/unit/deferred-recall-baseline.test.ts` and the e2e replay suites
exercise the Mind path with stub providers whose scripts do not depend on prompt text.

Live gate (record in `BASELINE.md`, parallel runtime, 3 trials each on gpt-4o and gemini-2.5-flash):
`action-with-speech.json` still calls `give_item` 3/3; `unmoderated-abuse.json` still exits 3/3;
`deferred-recall-strict.json` still passK 1; and the Mind's `cached_input_tokens` is non-zero on the
second and later turns on OpenAI (the stable Mind prefix is well above the 1,024-token floor).
Compare Mind p50 before and after.
